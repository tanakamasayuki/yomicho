# 使い方

日本語の原稿にルビを振るまでの流れです。細かいオプションは[コマンドリファレンス](CLI.ja.md)を、設計の理由は[仕様](spec.ja.md)を見てください。

## 準備

まだ npm に公開していないので、リポジトリから使います。Node.js 20 以降が要ります。

```sh
git clone https://github.com/tanakamasayuki/yomicho.git
cd yomicho
npm install
node bin/yomicho.js --help
```

## 考え方

読み帳は自動変換ツールではなく、**翻訳メモリ**です。

読みを推定するのは下書きを作るときだけで、一度決めた読みは原稿ごとの辞書に記録されます。共通辞書が後から変わっても、その原稿の出力は変わりません。

作業は3つの段階に分かれます。

```
update   原稿を見て、読みが要る語を集める
編集     人が読みを埋める、または承認する
build    原稿辞書だけで変換する
```

## 1. 語を集める

原稿がこうだとします。

```text
新型の未知製品を発表した。
日本橋へ行く。
```

```sh
yomicho update book.md
```

```
book.tsv: 6 行 (+6) / 要対応 6
```

原稿の隣に `book.tsv` ができます。これがこの原稿の辞書です。

```text
新型		{新型}の未知製品を発表した。
日本橋		{日本橋}へ行く。
未知		新型の{未知}製品を発表した。
発表		新型の未知製品を{発表}した。
行く		日本橋へ{行く}。
製品		新型の未知{製品}を発表した。
```

まだ何も分かっていないので読みは全部空欄で、3列目に出現箇所が入っています。

> `未知製品` が `未知` と `製品` に分かれていることに注意してください。語の切り出しは
> `Intl.Segmenter` に任せていて、複合語は分かれます。読みは誤りませんが、
> ひとまとまりで扱いたい固有名詞は自分で1行足すことになります。

すでに育てた辞書があるなら、参照辞書として渡します。

```sh
yomicho update book.md -d ../global.tsv
```

```
book.tsv: 6 行 (+6) / 要対応 2
```

引けた分には `>` が付き、要対応が 6 から 2 に減りました。引けた行のスニペットは外れます。

```text
新型	>しんがた
日本橋	>にほんばし
発表	>はっぴょう
行く	>いく
未知		新型の{未知}製品を発表した。
製品		新型の未知{製品}を発表した。
```

## 2. 読みを埋める

`book.tsv` を開くと、**下端がそのまま作業リスト**になっています。並び順が「確定 → `#` → `!` → `>` → `+` → 空欄」なので、手を入れるべき行が下に集まります。

空欄を埋めれば終わりです。3列目のスニペットに、その語が原稿のどこに出たかが書いてあります。

### AI に手伝ってもらう

数が多いときは書き出して投げます。

```sh
yomicho unresolved book.md > ask.tsv
```

```
未知		新型の{未知}製品を発表した。
製品		新型の未知{製品}を発表した。
```

整形していないので、そのまま貼れます。文脈が付いているので、表記だけ渡すより精度が上がります。

埋まったものを戻します。

```sh
yomicho merge book.md < filled.tsv
```

```
book.tsv: 取り込み 2
```

```text
未知	+みち	新型の{未知}製品を発表した。
製品	+せいひん	新型の未知{製品}を発表した。
```

**`+` が付きます。** 外から来た読みは未承認の扱いで、そのままでは資産になりません。

### 承認する

`+` を1文字消せば承認です。次の `update` でスニペットも外れ、行が上に移動します。

```text
未知	みち
製品	せいひん
```

## 3. 変換する

```sh
yomicho build book.md -o out.md
```

```html
<ruby>新型<rt>しんがた</rt></ruby>の<ruby>未知<rt>みち</rt></ruby><ruby>製品<rt>せいひん</rt></ruby>を<ruby>発表<rt>はっぴょう</rt></ruby>した。
<ruby>日本橋<rt>にほんばし</rt></ruby>へ<ruby>行<rt>い</rt></ruby>く。
```

送り仮名の `く` にルビが乗っていないことに注目してください。読みを漢字に割り当てられる場合は分けます。

`build` は `book.tsv` しか読みません。参照辞書も解析器も要らないので、**`book.md` と `book.tsv` だけあれば誰の環境でも同じ結果になります**。

## 覚えておくとよいこと

**読みが分からない語には、ルビを付けません。** 語の一部だけにルビを振って誤った読みを作るくらいなら、無ルビにして未解決として報告します。`BMP280` の `BMP` だけにルビを付けると `280` が読まれないので、そういう出力はしません。

**`update` は既存の行を書き換えません。** 何度実行しても、一度決めた読みは変わりません。参照辞書の値を採り直したいときは、その行を消してから `update` してください。

**ルビを振りたくない語には `#` を書きます。** `CUR	#カレント` なら、ルビは出ませんが読みは残るので読み上げには使えます。読みも要らなければ `#` だけです。

**同じ表記で読みが違うときは、見出しに文脈を書けます。**

```text
日本橋	にほんばし
大阪の{日本橋}	にっぽんばし
```

`{}` で囲んだ部分だけが置換の対象で、外側は照合にしか使いません。「大阪の」は消費されないので、そこにも別のルビが付きます。
